kiss-signKeep it simple, stupid, and sign.

An AI writes templates. A fixed program runs them and decides the verdict. You sign only on MATCH.

Who acts: You, the signer AI agent Program

Set up onceon your computer

  1. Fork, clone, init You
    Fork kiss-sign on GitHub, clone your fork, pnpm install, pnpm kiss-sign init --safe 0x…
    • Your fork's main is the one verify trusts. GitHub
    • API keys go in $KISS_SIGN_HOME/.env, never in the chat.
↓ The AI may work on the same computer

Build a templateonce per operation, with an AI agent

  1. State the intent You
    “Deposit USDC into the Morpho Apex vault”
  2. Research AI agent
    • Official addresses and what the protocol says about them Official siteGitHubProtocol API, if any
    • Contract name and creator Etherscan
    • Protocol health hacks, audits, upgrades DefiLlama hacks
    • Past transactions the program finds and counts them, and traces each one that is exactly the template (who calls whom); the AI reads the counts AlchemyEtherscandrpc trace
  3. Prove Program
    • Sources match public listings findings go to the report DefiLlamaCoinGeckoSource page
    • Code pins each address's code, and since when it ran Alchemydrpc
    • ABI matches the chain Etherscan → pinned solc = bytecode, but for masked positions
    • Vault history Alchemydrpc
    • ERC-7730 descriptors and who attested them ERC-7730 registry
  4. Write the report Program
    From the recordings, never by the AI: a Markdown report and, with the AI's notes, an HTML report with a confidence level per address.
  5. Open a pull request AI agent
    The template, its test transactions, the AI's notes, and the report. It never merges a template, registry or program gate pull request.
  6. Review and merge You
    Read the report, run pnpm report … --compare to check its facts again live, then merge. Merging is your approval. GitHub
↓ git pull brings the merged template to your clone

Every signingin your own terminal

  1. Approve the template You
    First use, and again whenever it changes: template approve shows the template's file, its commit and its hash, and records the hash.
  2. Fill the card You
    Pick each vault, market or recipient from a numbered list with full addresses. Type amounts in whole tokens, with decimals the program reads. The first time a template or vault is used, start with a small amount, as the report advises. Alchemydrpc
  3. Seal the card You
    Hashed and stored before you see the transaction.
  4. Propose on Safe You
    kiss-sign reads it back and recomputes every hash. Safe Transaction Service
  5. Verify Program
    • Self-check the clone is exactly your fork's main
    • Approval the template's hash is the one you approved
    • Decode byte for byte, every field against the template and the card
    • Mutations each changed copy must give MISMATCH, or the verdict is UNVERIFIABLE
    • Code pins every registry contract runs its pinned code
    • Simulate balances, allowances and views must match the card Alchemydrpc
  6. Verdict Program
    MATCH · MISMATCH · UNVERIFIABLE
  7. Independent check You · hardened tier
    On a second computer with no AI and no kiss-sign, check.sh <nonce> computes the hashes and decodes each call. Compare its hashes with the wallet, its 比對清單 row by row with verify's page, and the calls with what you meant. Safe Transaction ServiceSourcify
  8. Sign on the wallet You
    Only on MATCH: compare both hashes on the device's screen. Hardware wallet
