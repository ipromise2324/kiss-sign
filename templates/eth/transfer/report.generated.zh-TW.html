下一步

  1. 第一次用這個模板，或模板改過之後，先核准它
    bin/kiss-sign template approve eth/transfer

    它印出模板、GitHub 上 main 的 commit 和模板的 keccak256。是你審過的那份才回答 y。

  2. 收款人不是你的 Safe 時，先把它加進地址簿。名字自己取，用小寫英文和 - 連接；地址從聊天以外的來源取得
    bin/kiss-sign book add <name> <address>

    它印出名字和完整地址，問 Add this entry? [y/N] 。每個字元都跟聊天以外的來源核對過才打 y 。同一個收款人只要加一次。

  3. 做卡片
    bin/kiss-sign card new eth/transfer

    你這份 clone 的 templates/ 或 registry/ 跟 GitHub 上的 main 不一樣時，它什麼都不問就停下，叫你先跑 git pull 。

  4. 收款人（recipient）：它列出你的 Safe 和地址簿裡的名字，每個附完整地址。選你要的那個，完整地址要對。
  5. 金額（amount）：打 ETH 的數量，用整顆幣，例如 1250.5 ；可以有千位逗號，例如 1,000,611.448606 。

    它在問 [y/N] 之前顯示的卡片列出整顆和 base units 兩種寫法，核對數字是你要的。

  6. 它印出整張卡片，每個名字都附完整地址，最後問 Is this what you mean to do? [y/N] 。全部是你要的才打 y 。

    它印出 Sealed card 0x… ，這是卡片的 hash，下一步要用。

  7. 在 Safe web app 提出交易（第一次用這個模板，先用小額），複製它的 safeTxHash，然後跑
    bin/kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH：它印出 safeTxHash 和一個網頁的路徑，網頁上有 domain hash、message hash 和比對清單，往下走。

    MISMATCH 或 UNVERIFIABLE：不要簽。看它列出的檢查，再看本報告「待確認」裡 AI 的判斷，可能說明原因。

  8. 加強等級：在獨立電腦上跑
    ./check.sh <nonce>

    它算出的 hash 跟硬體錢包比對；它的網頁上的比對清單跟 verify 網頁上的逐列比對。

  9. 硬體錢包上的 domain hash 和 message hash，跟 verify 網頁上的逐字比對，一樣才簽。
    比對domain hash 和 message hash，都是 0x 開頭 64 個字元

程式每次簽名自動做的事

  • 交易只有這 1 個呼叫，MultiSend 也一個個解開
  • 每個參數符合上面的規則，重新編碼要一模一樣
  • 模擬後 Safe 給出的 ETH 剛好是你填的金額
  • 沒有任何授權在交易後變高
