從 Safe 在 CoW Swap 下一張 USDC 和 USDT 之間的賣單AI 研究

cow/swap

Safe 呼叫 CoW 結算合約的 setPreSignature，預先簽一張賣單：剛好賣出卡片上的數量、至少換到卡片上的最低值、付給 Safe。事先要有給 CoW vault relayer 的授權。買單、可部分成交和帶手續費的訂單都會被拒絕。AI 研究

  • 交易地址 4 / 4 4 個地址都至少在 2 個地方確認：官方頁（GitHub 上的檔案算它的 GitHub 組織，跟文件網站是不同的地方）、協議 API、CoinGecko、登記工廠（連同它的檢查問到的其他合約）、Immunefi 漏洞賞金範圍、釘選的 SDK 套件或共用的部署者列出同一個地址。
  • 參考地址 4 / 4 4 個參考地址只需 1 個地方確認：交易不會碰到它們，card new 只從它們讀一個數字，由你確認。價格來源錯了會壓低最少收到的數量，只有這組代幣有池子時才會拿池子的平均價格比對。
  • 原始碼驗證 7 / 7 Etherscan 上驗證的原始碼用固定版本的編譯器重新編譯，跟鏈上的程式碼一模一樣，所以解碼交易用的函式定義確實屬於這些合約。usdc、usdt、chainlink-usdc-usd、chainlink-usdt-usd 重新編譯後只有 metadata hash 跟鏈上不同，所以函式選擇器和參數型別有證明，算通過；參數名稱沒有證明。gpv2-vault-relayer 沒有呼叫直接打到，也不用它的函式定義解碼，所以沒有證明，不算在內；它跑的程式碼在「合約沒被換掉」比對。
  • 合約沒被換掉 8 / 8 每次簽名都確認卡片用到的每個合約還是研究時那份程式碼。被升級或換掉就擋下。chainlink-usdc-usd、chainlink-usdt-usd、uniswap-v3-factory、uniswap-v3-usdc-usdt-100 簽名時不碰，只有報告比對它的程式碼。gpv2-vault-relayer 沒有 ABI 證明比對它今天的程式碼，報告另外在最新區塊讀它跑的程式碼，跟 code pin 現在那一份比對。
  • 參數保護 沒有測試 交易裡不限的值只在簽的訂單裡，由雜湊鎖住，不換值測試。模板沒有不限的參數：每個參數都綁定卡片或固定值，沒有參數要換值測試，所以沒有換值測試的記錄。每次簽名，verify 都把每個綁定的參數逐一改掉，確認都變成 MISMATCH。
  • 雙節點比對 鏈上資料都同時問兩家節點，答案不一樣就不給結果。研究時有三種資料只有一個來源，都不會影響判定：過去交易的呼叫追蹤（drpc）、搜尋過去交易（Alchemy 或 Etherscan 找到的都算，找事件只用 Etherscan），和金庫曾經收過份額的地址名單（Alchemy，每個地址的餘額仍問兩家）。
建議訂單綁定你的數量；之後由 solver 成交，訂單在到期前都有效。AI 研究：要小心

下一步

  1. 核准前，到「地址」逐一打開每個地址的來源，確認每個網域都是協議自己的，而且頁面上列著這個地址。
  2. 第一次用這個模板，或模板改過之後，先核准它
    pnpm kiss-sign template approve cow/swap

    它印出模板、GitHub 上 main 的 commit 和模板的 keccak256。是你審過的那份才回答 y。

  3. 做卡片
    pnpm kiss-sign card new cow/swap

    你這份 clone 的 templates/ 或 registry/ 跟 GitHub 上的 main 不一樣時，它什麼都不問就停下，叫你先跑 git pull 。

  4. 代幣（sell-token）：它列出可選的代幣，每個附完整地址。選你要的那個，名字和完整地址都要對。
  5. 代幣（buy-token）：它列出可選的代幣，每個附完整地址。選你要的那個，名字和完整地址都要對。
  6. 金額（sell-amount）：打 你選的代幣（sell-token） 的數量，用整顆幣，例如 1250.5 ；可以有千位逗號，例如 1,000,611.448606 。

    它在問 [y/N] 之前顯示的卡片列出整顆和 base units 兩種寫法，核對數字是你要的。

  7. 最少收到的數量（min-buy）：程式用你選的兩個代幣的獨立價格，替 sell-amount 算最少要收到多少。

    usdc 換 usdt：即時檢查都通過時程式算，價格來源是 chainlink-usdc-usd、chainlink-usdt-usd；第二來源是池子 uniswap-v3-usdc-usdt-100（流動性至少 6660000000000）。

    usdt 換 usdc：即時檢查都通過時程式算，價格來源是 chainlink-usdt-usd、chainlink-usdc-usd；第二來源是池子 uniswap-v3-usdc-usdt-100（流動性至少 6660000000000）。

    兩個代幣都有價格來源、又錨定同一個價格時，它問 app 顯示的滑價（按 Enter 是 0.50%，最多 1.00%），印出讀到的價格，取比較嚴的那個，扣掉滑價和 0.25% 餘裕，無條件捨去。這個餘裕是程式定的，每組代幣都一樣，留給價格來源本身的誤差和 app 最少收到數量裡的手續費。核對 app 的最少收到數量不低於它印出的 你選的代幣（buy-token） 數量。

    「程式算」只在 card new 簽名當下的檢查都通過時成立：每個價格來源夠新、錨定的代幣離錨定價不遠、價格來源和池子的價格相符、池子流動性夠也讀得到。任何一項沒過，它會說是哪一項，改成你填 app 顯示的最少收到數量，而且要填兩次一樣的數量。

    AI池子 uniswap-v3-usdc-usdt-100 的最低流動性 6660000000000：由 AI 選定，不是協議或它的 app 定的。理由：pnpm pool-depth --auto 取樣 366 天：平穩 41137149129847228（區塊 25969908），壓力與最低 6660026988514（區塊 26301108），30 分鐘窗口（這組同錨定代幣用的窗口）。取最低值往下取整成 6660000000000，讓池子在和量到最差一樣薄的日子仍能報價；366 天中 0 天低於它。

  8. 它印出整張卡片，每個名字都附完整地址，最後問 Is this what you mean to do? [y/N] 。全部是你要的才打 y 。

    它印出 Sealed card 0x… ，這是卡片的 hash，下一步要用。

  9. 在 Safe web app 提出交易（第一次用這個模板，先用小額），複製它的 safeTxHash，然後跑
    pnpm kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH：它印出 safeTxHash 和一個網頁的路徑，網頁上有 domain hash、message hash 和比對清單，往下走。

    MISMATCH 或 UNVERIFIABLE：不要簽。看它列出的檢查，再看本報告「待確認」裡 AI 的判斷，可能說明原因。

  10. 加強等級：在獨立電腦上跑
    ./check.sh <nonce>

    它算出的 hash 跟硬體錢包比對；它的網頁上的比對清單跟 verify 網頁上的逐列比對。

  11. 硬體錢包上的 domain hash 和 message hash，跟 verify 網頁上的逐字比對，一樣才簽。

    用 Ledger 簽的話，先在 Ethereum app 的設定打開「Transaction hash」：套用描述檔時，要打開它裝置才會顯示 domain hash 和 message hash。比對這兩個 hash 才是 kiss-sign 靠的檢查，解讀看起來再對也要比。

    比對domain hash 和 message hash，都是 0x 開頭 64 個字元
