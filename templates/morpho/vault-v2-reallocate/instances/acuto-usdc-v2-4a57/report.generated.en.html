Move funds between two markets of a Morpho Vault V2 (allocator)AI research

morpho/vault-v2-reallocate · acuto-usdc-v2-4a57

As allocator, the Safe calls the vault's multicall: it withdraws the amount you type from the source market you pick and puts it into the target market you pick. Funds move only between the vault's markets. The only asset of the Safe that may change is the vault's own shares: allocate first accrues the vault's interest, which mints fee shares to the fee recipient, so a Safe that is that recipient gets some.AI research

  • Address sources 9 / 13 4 addresses have results for you to review; see "To review". The other 9 are all confirmed in at least 2 places.
  • Source verified 6 / 6 The source verified on Etherscan, compiled again with a pinned compiler, gives exactly the code on chain, so the function definitions used to decode the transaction belong to these contracts. adaptive-curve-irm, morpho-oracle-cbbtc-usdc-86, morpho-oracle-usp-usdc, acuto-usdc-v2-4a57-market-adapter, morpho-oracle-weeth-usdc-86: no call goes to it directly and no function definition of it decodes anything, so it has no proof and is not counted; the code it runs is compared under "Code unchanged".
  • Code unchanged 13 / 13 At each signing, the program checks that every contract the card uses still runs the code it was researched with. An upgrade or a replacement is stopped. Signing does not touch vault-v2-factory, morpho-market-v1-adapter-v2-factory; only the report compares their code. No ABI proof compares the code adaptive-curve-irm, morpho-oracle-cbbtc-usdc-86, morpho-oracle-usp-usdc, acuto-usdc-v2-4a57-market-adapter, morpho-oracle-weeth-usdc-86 runs today, so the report reads it at the latest block and compares it with the current code pin.
  • Parameter checks no tests The template has no argument that takes any value: each is bound to the card or to a fixed value, so nothing needs a perturbation test and none is recorded. At each signing, verify changes every bound argument one by one and checks that each becomes a MISMATCH.
  • Two providers Every chain read asks two providers; when they disagree, there is no result. Three research reads have one source, and none of them reaches a verdict: past transactions' call traces (drpc), the search for past transactions (a transaction either Alchemy or Etherscan finds counts; only Etherscan searches for an event), and the addresses that ever received a vault's shares (Alchemy; each one's balance is still read through both).
AdviceOK to use, but this is a small unlisted vault with concentrated holders, and only the factory confirms its address. See To review.AI research: be careful

no descriptor; the wallet shows only raw data
your Safe is a proxy: a Ledger resolves it to safe-1.3.0 or safe-1.4.1 through Ledger's own server to use these descriptors; a wallet that does not resolve proxies shows only raw data.
SafeTx: the wallet does not show safeTxGas, nonce; only the hashes cover them.
The Safe transaction may also wrap this one call in the official MultiSend (Delegate Call (1)), which verify accepts too: then to is the official MultiSend, value is 0, and the call shows only as raw data.
On a Ledger, first turn on "Transaction hash" in the Ethereum app's settings: with a descriptor applied, the device shows the domain hash and the message hash only when it is on. Comparing those hashes is the check kiss-sign relies on, however right the decoded fields look.
