morpho/vault-v2-cap-accept · sentora-rlusd-main-v2-e6bf

The Safe calls the vault's multicall with one increaseAbsoluteCap, which executes a raise of the market's absolute cap queued earlier with submit. It reverts unless that exact raise was queued and its timelock has passed. It moves none of the Safe's assets.AI research

  • Transaction addresses 7 / 9 2 addresses have results for you to review; see "To review". The other 7 are all confirmed in at least 2 places.
  • Source verified 5 / 5 The source verified on Etherscan, compiled again with a pinned compiler, gives exactly the code on chain, so the function definitions used to decode the transaction belong to these contracts. rlusd: compiled again, only the metadata hash differs from the code on chain, so its function selectors and parameter types are proven and it counts as passed; its parameter names are not proven. morpho-blue, adaptive-curve-irm, sentora-rlusd-main-v2-e6bf-market-adapter, morpho-oracle-kbtc-rlusd-86: no call goes to it directly and no function definition of it decodes anything, so it has no proof and is not counted; the code it runs is compared under "Code unchanged".
  • Code unchanged 9 / 9 At each signing, the program checks that every contract the card uses still runs the code it was researched with. An upgrade or a replacement is stopped. Signing does not touch vault-v2-factory, morpho-market-v1-adapter-v2-factory; only the report compares their code. No ABI proof compares the code morpho-blue, adaptive-curve-irm, sentora-rlusd-main-v2-e6bf-market-adapter, morpho-oracle-kbtc-rlusd-86 runs today, so the report reads it at the latest block and compares it with the current code pin.
  • Parameter checks no tests The template has no argument that takes any value: each is bound to the card or to a fixed value, so nothing needs a perturbation test and none is recorded. At each signing, verify changes every bound argument one by one and checks that each becomes a MISMATCH.
  • Two providers Every chain read asks two providers; when they disagree, there is no result. Three research reads have one source, and none of them reaches a verdict: past transactions' call traces (drpc), the search for past transactions (a transaction either Alchemy or Etherscan finds counts; only Etherscan searches for an event), and the addresses that ever received a vault's shares (Alchemy; each one's balance is still read through both).
