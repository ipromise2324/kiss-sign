存款去哪裡AI 研究

USDC 不會留在 vault 裡：同一筆交易中 vault 就把它交給流動性 adapter，adapter 再供應到一個 Morpho Blue 市場：以 WBTC 為抵押、LLTV 86% 的 USDC 市場（區塊 26,490,392）。allocator 隨時可以改成別的市場。 來源 1 來源 2 來源 3 來源 4

借給哪些市場AI 研究

vault 透過唯一的 adapter 借給 9 個 Morpho Blue 的 USDC 市場。allocator 在策展人對 adapter、抵押品和市場設的上限內搬動 USDC，所以每次重新分配，組合就會變。 來源 1 來源 2 來源 3

誰能改AI 研究

三個 allocator 隨時可以在上限內把資金搬到別的市場。策展人加 adapter 或調高上限要等 7 天，但新增 allocator、改手續費、設提款罰金可以立刻做。 來源 1 來源 2 來源 3

怎麼把 USDC 拿回來AI 研究

vault 裡沒有閒置的 USDC，提款由 adapter 供應的 WBTC 市場支付：vault 的 1.147 億 USDC 中約 4,760 萬能這樣提出（Morpho 的 API，2026-11-25）。超過的部分要等 allocator 把 USDC 撤回，或呼叫 forceDeallocate 並付罰金（目前 0.001%，策展人可以立刻調高到 2%）。 來源 1 來源 2 來源 3 來源 4

下一步

  1. 核准前，到「地址」逐一打開每個地址的來源，確認每個網域都是協議自己的，而且頁面上列著這個地址。
  2. 第一次用這個模板，或模板改過之後，先核准它
    pnpm kiss-sign template approve morpho/vault-deposit

    它印出模板、GitHub 上 main 的 commit 和模板的 keccak256。是你審過的那份才回答 y。

  3. 做卡片
    pnpm kiss-sign card new morpho/vault-deposit

    你這份 clone 的 templates/ 或 registry/ 跟 GitHub 上的 main 不一樣時，它什麼都不問就停下，叫你先跑 git pull 。

  4. 金庫（vault）：它列出可選的合約，每個附完整地址。選 steakhouse-prime-usdc-v2-0f51，地址是 0xbeef088055857739C12CD3765F20b7679Def0f51

    列表的編號可能跟別人的不同，照名字選；也可以直接打名字 steakhouse-prime-usdc-v2-0f51 。

  5. 金額（amount）：打 usdc 的數量，用整顆幣，例如 1250.5 ；可以有千位逗號，例如 1,000,611.448606 。

    它在問 [y/N] 之前顯示的卡片列出整顆和 base units 兩種寫法，核對數字是你要的。

  6. 最少收到的數量（min-shares）：不用填。協議的 app 自己會填這個值，不會問使用者，所以程式自己算。

    它在鏈上讀 previewDeposit，兩個節點答案一樣才用，印出預期的 steakhouse-prime-usdc-v2-0f51 數量，再少 0.10%（協議預設的 0.03%，再加 0.07% 餘裕），無條件捨去。

    預設值的來源：github.com/morpho-org/sdks。核對印出的預期數量跟最後的數字合理。

    AI0.07% 的餘裕：由 AI 選定，不是協議或它的 app 定的。理由：Morpho app 組交易時會重新計算一次存款價格。若期間每股價格往不利於卡片的方向變動，只用預設值的話，app 自己組的交易就會 MISMATCH。多 0.07% 大約夠年化 8% 的金庫三天的變動。

  7. 它印出整張卡片，每個名字都附完整地址，最後問 Is this what you mean to do? [y/N] 。全部是你要的才打 y 。

    它印出 Sealed card 0x… ，這是卡片的 hash，下一步要用。

  8. 在 Safe web app 提出交易（第一次用這個模板或這個合約，先用小額），複製它的 safeTxHash，然後跑
    pnpm kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH：它印出 safeTxHash 和一個網頁的路徑，網頁上有 domain hash、message hash 和比對清單，往下走。

    MISMATCH 或 UNVERIFIABLE：不要簽。看它列出的檢查，再看本報告「待確認」裡 AI 的判斷，可能說明原因。

  9. 加強等級：在獨立電腦上跑
    ./check.sh <nonce>

    它算出的 hash 跟硬體錢包比對；它的網頁上的比對清單跟 verify 網頁上的逐列比對。

  10. 硬體錢包上的 domain hash 和 message hash，跟 verify 網頁上的逐字比對，一樣才簽。

    用 Ledger 簽的話，先在 Ethereum app 的設定打開「Transaction hash」：套用描述檔時，要打開它裝置才會顯示 domain hash 和 message hash。比對這兩個 hash 才是 kiss-sign 靠的檢查，解讀看起來再對也要比。

    比對domain hash 和 message hash，都是 0x 開頭 64 個字元
