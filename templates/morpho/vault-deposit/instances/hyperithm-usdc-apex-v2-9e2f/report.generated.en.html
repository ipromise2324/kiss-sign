morpho/vault-deposit · hyperithm-usdc-apex-v2-9e2f

Approves exactly the amount of the vault's asset to Morpho's VaultBundlesV1, which pulls it and deposits it into the vault for your Safe, reverting if the share price is above the bound the card's fewest shares give. Refuses a referral fee, a permit, an approval larger than the amount, and a deadline more than 2 hours ahead.AI research

  • Transaction addresses 5 / 6 1 address has results for you to review; see "To review". The other 5 are all confirmed in at least 2 places.
  • Source verified 5 / 5 The source verified on Etherscan, compiled again with a pinned compiler, gives exactly the code on chain, so the function definitions used to decode the transaction belong to these contracts. usdc: compiled again, only the metadata hash differs from the code on chain, so its function selectors and parameter types are proven and it counts as passed; its parameter names are not proven. hyperithm-usdc-apex-v2-9e2f-market-adapter: no call goes to it directly and no function definition of it decodes anything, so it has no proof and is not counted; the code it runs is compared under "Code unchanged".
  • Code unchanged 6 / 6 At each signing, the program checks that every contract the card uses still runs the code it was researched with. An upgrade or a replacement is stopped. Signing does not touch vault-v2-factory, hyperithm-usdc-apex-v2-9e2f-market-adapter, morpho-market-v1-adapter-v2-factory; only the report compares their code. No ABI proof compares the code hyperithm-usdc-apex-v2-9e2f-market-adapter runs today, so the report reads it at the latest block and compares it with the current code pin.
  • Parameter checks no tests The template has no argument that takes any value: each is bound to the card or to a fixed value, so nothing needs a perturbation test and none is recorded. At each signing, verify changes every bound argument one by one and checks that each becomes a MISMATCH.
  • Call traces 2 / 2 The program looks for each of the AI's flow lines in the call traces of past transactions, and checks that the template or a flow line explains every call inside that moves money; 2 of 2 passed. The traces come from drpc alone; their token transfers and approvals are checked against the receipt both providers agree on.
  • Two providers Every chain read asks two providers; when they disagree, there is no result. Three research reads have one source, and none of them reaches a verdict: past transactions' call traces (drpc), the search for past transactions (a transaction either Alchemy or Etherscan finds counts; only Etherscan searches for an event), and the addresses that ever received a vault's shares (Alchemy; each one's balance is still read through both).
