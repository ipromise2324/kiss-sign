Lower a Morpho Vault V2 market cap (curator or sentinel)AI research

morpho/vault-v2-cap-decrease · acuto-usdc-v2-4a57

The Safe calls the vault's multicall to lower, right away, the absolute cap of the market you pick to the amount you type, and its relative cap to the percentage you type. Lowering does not wait for a timelock. It moves none of the Safe's assets.AI research

  • Address sources 9 / 13 4 addresses have results for you to review; see "To review". The other 9 are all confirmed in at least 2 places.
  • Source verified 6 / 6 The source verified on Etherscan, compiled again with a pinned compiler, gives exactly the code on chain, so the function definitions used to decode the transaction belong to these contracts. morpho-blue, adaptive-curve-irm, morpho-oracle-cbbtc-usdc-86, morpho-oracle-usp-usdc, acuto-usdc-v2-4a57-market-adapter, morpho-oracle-weeth-usdc-86: no call goes to it directly and no function definition of it decodes anything, so it has no proof and is not counted; the code it runs is compared under "Code unchanged".
  • Code unchanged 13 / 13 At each signing, the program checks that every contract the card uses still runs the code it was researched with. An upgrade or a replacement is stopped. Signing does not touch vault-v2-factory, morpho-market-v1-adapter-v2-factory; only the report compares their code. No ABI proof compares the code morpho-blue, adaptive-curve-irm, morpho-oracle-cbbtc-usdc-86, morpho-oracle-usp-usdc, acuto-usdc-v2-4a57-market-adapter, morpho-oracle-weeth-usdc-86 runs today, so the report reads it at the latest block and compares it with the current code pin.
  • Parameter checks no tests The template has no argument that takes any value: each is bound to the card or to a fixed value, so nothing needs a perturbation test and none is recorded. At each signing, verify changes every bound argument one by one and checks that each becomes a MISMATCH.
  • Two providers Every chain read asks two providers; when they disagree, there is no result. Three research reads have one source, and none of them reaches a verdict: past transactions' call traces (drpc), the search for past transactions (a transaction either Alchemy or Etherscan finds counts; only Etherscan searches for an event), and the addresses that ever received a vault's shares (Alchemy; each one's balance is still read through both).
AdviceOK to use, but this is a small unlisted vault with concentrated holders, and only the factory confirms its address. See To review.AI research: be careful

Next steps

  1. The first time you use this template, or after it changes, approve it
    bin/kiss-sign template approve morpho/vault-v2-cap-decrease

    It prints the template, the commit of main on GitHub and the template's keccak256. Answer y only if it is the one you reviewed.

  2. Make the card
    bin/kiss-sign card new morpho/vault-v2-cap-decrease

    When templates/ or registry/ in your clone differs from main on GitHub, it stops before asking anything and tells you to run git pull first.

  3. vault: it lists the contracts you can pick, each with its full address. Pick acuto-usdc-v2-4a57, address 0x153Bd1abE60104Bd46aa05a27fA12D1346D64A57

    The numbers in the list may differ from someone else's, so pick by name; you can also type the name acuto-usdc-v2-4a57.

  4. market: it lists each market with its id, its lltv and the full address of each part. Pick the market you want; its id must be right.
  5. amount (absolute-cap): type the amount of usdc in whole tokens, such as 1250.5; thousands commas are allowed, such as 1,000,611.448606.

    The card it shows before asking [y/N] gives it both in whole tokens and in base units; check that the number is what you want.

  6. percent (relative-cap): type a percent, at most 100, such as 100 or 35.5.

    The card it shows before asking [y/N] gives the percent and the base units (100% is 10^18); check that the number is what you want.

  7. It prints the whole card, each name with its full address, and asks Is this what you mean to do? [y/N]. Type y only if all of it is what you want.

    It prints Sealed card 0x…, the card's hash, which the next step uses.

  8. Propose the transaction in the Safe web app (the first time you use this template or this contract, start with a small amount), copy its safeTxHash, then run
    bin/kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH: it prints the safeTxHash and the path of a page with the domain hash, the message hash and the checklist. Go on.

    MISMATCH or UNVERIFIABLE: do not sign. Read the checks it lists, then the AI judgment under "To review" in this report, which may explain why.

  9. Hardened tier: on an independent computer, run
    ./check.sh <nonce>

    Compare the hashes it computes with the hardware wallet, and its page's checklist row by row with the verify page.

  10. Compare the domain hash and the message hash on the hardware wallet character by character with the verify page. Sign only if they are the same.
