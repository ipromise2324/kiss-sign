取消排隊中的 Morpho Vault V2 上限提高（curator 或 sentinel）AI 研究

morpho/vault-v2-revoke · acuto-usdc-v2-4a57

Safe 呼叫 vault 的 multicall，裡面兩個 revoke：取消之前 submit 排隊、還沒執行的絕對上限和相對上限提高。取消後 executableAt 歸零，那兩個呼叫不能再執行。不動 Safe 的任何資產。AI 研究

  • 地址來源 9 / 13 4 個地址有結果要你看，見「待確認」。其餘 9 個都至少在 2 個地方確認。
  • 原始碼驗證 6 / 6 Etherscan 上驗證的原始碼用固定版本的編譯器重新編譯，跟鏈上的程式碼一模一樣，所以解碼交易用的函式定義確實屬於這些合約。morpho-blue、adaptive-curve-irm、morpho-oracle-cbbtc-usdc-86、morpho-oracle-usp-usdc、acuto-usdc-v2-4a57-market-adapter、morpho-oracle-weeth-usdc-86 沒有呼叫直接打到，也不用它的函式定義解碼，所以沒有證明，不算在內；它跑的程式碼在「合約沒被換掉」比對。
  • 合約沒被換掉 13 / 13 每次簽名都確認卡片用到的每個合約還是研究時那份程式碼。被升級或換掉就擋下。vault-v2-factory、morpho-market-v1-adapter-v2-factory 簽名時不碰，只有報告比對它的程式碼。morpho-blue、adaptive-curve-irm、morpho-oracle-cbbtc-usdc-86、morpho-oracle-usp-usdc、acuto-usdc-v2-4a57-market-adapter、morpho-oracle-weeth-usdc-86 沒有 ABI 證明比對它今天的程式碼，報告另外在最新區塊讀它跑的程式碼，跟 code pin 現在那一份比對。
  • 參數保護 沒有測試 模板沒有不限的參數：每個參數都綁定卡片或固定值，沒有參數要換值測試，所以沒有換值測試的記錄。每次簽名，verify 都把每個綁定的參數逐一改掉，確認都變成 MISMATCH。
  • 雙節點比對 鏈上資料都同時問兩家節點，答案不一樣就不給結果。研究時有三種資料只有一個來源，都不會影響判定：過去交易的呼叫追蹤（drpc）、搜尋過去交易（Alchemy 或 Etherscan 找到的都算，找事件只用 Etherscan），和金庫曾經收過份額的地址名單（Alchemy，每個地址的餘額仍問兩家）。
建議可以用，但這是沒上架的小 vault，持有人集中；地址只有工廠確認，見待確認。AI 研究：要小心

下一步

  1. 核准前，到「地址」逐一打開每個地址的來源，確認每個網域都是協議自己的，而且頁面上列著這個地址。
  2. 第一次用這個模板，或模板改過之後，先核准它
    pnpm kiss-sign template approve morpho/vault-v2-revoke

    它印出模板、GitHub 上 main 的 commit 和模板的 keccak256。是你審過的那份才回答 y。

  3. 做卡片
    pnpm kiss-sign card new morpho/vault-v2-revoke

    你這份 clone 的 templates/ 或 registry/ 跟 GitHub 上的 main 不一樣時，它什麼都不問就停下，叫你先跑 git pull 。

  4. 金庫（vault）：它列出可選的合約，每個附完整地址。選 acuto-usdc-v2-4a57，地址是 0x153Bd1abE60104Bd46aa05a27fA12D1346D64A57

    列表的編號可能跟別人的不同，照名字選；也可以直接打名字 acuto-usdc-v2-4a57 。

  5. 市場（market）：它列出每個市場的 id、lltv 和每個組成的完整地址。選你要的市場，id 要對。
  6. 金額（absolute-cap）：打 usdc 的數量，用整顆幣，例如 1250.5 ；可以有千位逗號，例如 1,000,611.448606 。

    它在問 [y/N] 之前顯示的卡片列出整顆和 base units 兩種寫法，核對數字是你要的。

    也可以打 max，等於 340282366920938463463374607431768211455 base units；card new 會印出模板寫的理由。

  7. 百分比（relative-cap）：打百分比，最多 100，例如 100 或 35.5 。

    它在問 [y/N] 之前顯示的卡片列出百分比和 base units（100% 是 10^18），核對數字是你要的。

  8. 它印出整張卡片，每個名字都附完整地址，最後問 Is this what you mean to do? [y/N] 。全部是你要的才打 y 。

    它印出 Sealed card 0x… ，這是卡片的 hash，下一步要用。

  9. 在 Safe web app 提出交易（第一次用這個模板或這個合約，先用小額），複製它的 safeTxHash，然後跑
    pnpm kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH：它印出 safeTxHash 和一個網頁的路徑，網頁上有 domain hash、message hash 和比對清單，往下走。

    MISMATCH 或 UNVERIFIABLE：不要簽。看它列出的檢查，再看本報告「待確認」裡 AI 的判斷，可能說明原因。

  10. 加強等級：在獨立電腦上跑
    ./check.sh <nonce>

    它算出的 hash 跟硬體錢包比對；它的網頁上的比對清單跟 verify 網頁上的逐列比對。

  11. 硬體錢包上的 domain hash 和 message hash，跟 verify 網頁上的逐字比對，一樣才簽。

    用 Ledger 簽的話，先在 Ethereum app 的設定打開「Transaction hash」：套用描述檔時，要打開它裝置才會顯示 domain hash 和 message hash。比對這兩個 hash 才是 kiss-sign 靠的檢查，解讀看起來再對也要比。

    比對domain hash 和 message hash，都是 0x 開頭 64 個字元
