Deposit into a Fluid lending pool (fToken)AI research

fluid/vault-deposit · fluid-fusdc

The Safe first gives the fToken you pick an allowance of exactly the amount you type, then calls deposit on the same fToken. Through Fluid's Liquidity contract, the fToken pulls these tokens from the Safe and mints fToken shares to the Safe. When depositing, the Fluid app asks only for the amount and sets no minimum shares, so the card asks only for the vault and the amount.AI research

  • Address sources 4 / 4 All 4 addresses are confirmed in at least 2 places: the official page, the protocol API, CoinGecko, the registered factory (for an adapter, with the vault that uses it), the bug bounty scope, the SDK package or a shared deployer lists the same address.
  • Source verified 2 / 2 The source verified on Etherscan, compiled again with a pinned compiler, gives exactly the code on chain, so the function definitions used to decode the transaction belong to these contracts. fluid-liquidity: no call goes to it directly and no function definition of it decodes anything, so it has no proof and is not counted; the code it runs is compared under "Code unchanged".
  • Code unchanged 4 / 4 At each signing, the program checks that every contract the card uses still runs the code it was researched with. An upgrade or a replacement is stopped. Signing does not touch fluid-lending-factory; only the report compares its code. No ABI proof compares the code fluid-liquidity runs today, so the report reads it at the latest block and compares it with the current code pin. fluid-liquidity: it routes each call by function selector to its own implementation; each implementation the seeds reach, with its function list, is checked the same way, and one no seed reaches is not checked.
  • Parameter checks 2 / 2 The program changed every bound argument of 2 test transactions one by one, and each must become a MISMATCH; an argument that takes any value must give the same result with another value.
  • Two providers Every chain read asks two providers; when they disagree, there is no result.
AdviceUsable. The tokens are actually held in Fluid's Liquidity contract, and at every signing the program checks that its code is unchanged. Send a small amount the first time.AI research: be careful

To review 3

The AI checked each item first and gives its advice.

The deposited tokens are held in Fluid's Liquidity contract, an upgradeable InfiniteProxy. At every signing the program checks that it and its 4 implementations are unchanged. After an upgrade, verify gives MISMATCH until a new code pin is merged. The program does not see an implementation that only adds brand-new functions; Fluid did that once, at block 24,649,359. source 1 source 2AI research
AdviceIf verify gives MISMATCH, do not sign. After Fluid upgrades, wait until the new code pin is merged before you deposit.AI research
deposit sets no minimum shares. Every EOA that deposited by calling an fToken directly over the past year used this two-argument version; none used the version with minAmountOut_. By the contract's design, the fToken's exchange price comes from Liquidity's interest accrual and only rises, never falls, so it is hard to push the price up at the moment you deposit. sourceAI research
AdviceAcceptable. If it matters to you, after verify check the number of shares the Safe actually received.AI research
fUSDC held about 283 million USDC a year ago, about 314 million in 2026-01, and about 135 million now. From 2026-05 to 06 it lost about 83 million in one month, at the same time as the reward private key incident (Fluid says the lending pools were not affected). 2,128 addresses hold it, and the top 10 hold 39.24%. sourceAI research
AdviceThis pool has existed for more than a year. Fluid's withdrawal limits may delay a large withdrawal, so before you deposit, plan when you will withdraw.AI research

Next steps

  1. The first time you use this template, or after it changes, approve it
    bin/kiss-sign template approve fluid/vault-deposit

    It prints the template, the commit of main on GitHub and the template's keccak256. Answer y only if it is the one you reviewed.

  2. Make the card
    bin/kiss-sign card new fluid/vault-deposit

    When templates/ or registry/ in your clone differs from main on GitHub, it stops before asking anything and tells you to run git pull first.

  3. vault: it lists the contracts you can pick, each with its full address. Pick fluid-fusdc, address 0x9Fb7b4477576Fe5B32be4C1843aFB1e55F251B33

    The numbers in the list may differ from someone else's, so pick by name; you can also type the name fluid-fusdc.

  4. amount: type the amount of usdc in whole tokens, such as 1250.5; thousands commas are allowed, such as 1,000,611.448606.

    The card it shows before asking [y/N] gives it both in whole tokens and in base units; check that the number is what you want.

  5. It prints the whole card, each name with its full address, and asks Is this what you mean to do? [y/N]. Type y only if all of it is what you want.

    It prints Sealed card 0x…, the card's hash, which the next step uses.

  6. Propose the transaction in the Safe web app (the first time you use this template or this vault, start with a small amount), copy its safeTxHash, then run
    bin/kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH: it prints the safeTxHash and the path of a page with the domain hash, the message hash and the checklist. Go on.

    MISMATCH or UNVERIFIABLE: do not sign. Read the checks it lists, then the AI judgment under "To review" in this report, which may explain why.

  7. Hardened tier: on an independent computer, run
    ./check.sh <nonce>

    Compare the hashes it computes with the hardware wallet, and its page's checklist row by row with the verify page.

  8. Compare the domain hash and the message hash on the hardware wallet character by character with the verify page. Sign only if they are the same.
    Comparethe domain hash and the message hash, each 0x followed by 64 characters
