更換 Safe 的簽署人AI 研究

safe/swap-owner

Safe 呼叫自己的 swapOwner，把舊簽署人換成新簽署人，門檻不變。prevOwner 由程式在鏈上讀 getOwners 算出，不用你填。AI 研究

  • 地址來源 2 / 2 2 個地址都至少在 2 個地方確認：官方頁（GitHub 上的檔案算它的 GitHub 組織，跟文件網站是不同的地方）、協議 API、CoinGecko、登記工廠（連同它的檢查問到的其他合約）、Immunefi 漏洞賞金範圍、釘選的 SDK 套件或共用的部署者列出同一個地址。
  • 原始碼驗證 2 / 2 Etherscan 上驗證的原始碼用固定版本的編譯器重新編譯，跟鏈上的程式碼一模一樣，所以解碼交易用的函式定義確實屬於這些合約。
  • 合約沒被換掉 2 / 2 每次簽名都確認卡片用到的每個合約還是研究時那份程式碼。被升級或換掉就擋下。safe-1.3.0、safe-1.4.1 簽名時不碰，只有報告比對它的程式碼。
  • 參數保護 沒有測試 模板沒有不限的參數：每個參數都綁定卡片或固定值，沒有參數要換值測試，所以沒有換值測試的記錄。每次簽名，verify 都把每個綁定的參數逐一改掉，確認都變成 MISMATCH。
  • 雙節點比對 鏈上資料都同時問兩家節點，答案不一樣就不給結果。研究時有三種資料只有一個來源，都不會影響判定：過去交易的呼叫追蹤（drpc）、搜尋過去交易（Alchemy 或 Etherscan 找到的都算），和金庫曾經收過份額的地址名單（Alchemy，每個地址的餘額仍問兩家）。
建議不動任何資產，但改的是誰能動這個 Safe：新簽署人的地址要從聊天以外的來源核對。AI 研究：要小心

其他做法

只算用了這個操作的呼叫的交易。跟模板一模一樣，指交易的呼叫和參數位置跟模板相同，從交易本身看得出來的參數規定（例如該填送出者的地方、固定值）都成立，模板綁定 registry 合約的地方也是模板允許的合約。形狀一樣、但用的是 registry 外的市場、代幣、金庫或地址，指呼叫、參數位置和這些參數規定都一樣，但有地址或市場不在 registry 裡；種類照記錄看得出的寫，看不出就只說地址。其他的依原因分組，各附最多 3 筆例子。

下一步

  1. 第一次用這個模板，或模板改過之後，先核准它
    bin/kiss-sign template approve safe/swap-owner

    它印出模板、GitHub 上 main 的 commit 和模板的 keccak256。是你審過的那份才回答 y。

  2. 先把要加、要移除或要換的簽署人加進地址簿。名字自己取，用小寫英文和 - 連接；地址從聊天以外的來源取得
    bin/kiss-sign book add <name> <address>

    它印出名字和完整地址，問 Add this entry? [y/N] 。每個字元都跟聊天以外的來源核對過才打 y 。同一個人只要加一次。

  3. 做卡片
    bin/kiss-sign card new safe/swap-owner

    你這份 clone 的 templates/ 或 registry/ 跟 GitHub 上的 main 不一樣時，它什麼都不問就停下，叫你先跑 git pull 。

  4. 簽署人（old-owner）：它列出地址簿裡的名字，每個附完整地址。選你要的那個簽署人，完整地址要對。
  5. 簽署人（new-owner）：它列出地址簿裡的名字，每個附完整地址。選你要的那個簽署人，完整地址要對。
  6. 它印出整張卡片，每個名字都附完整地址，最後問 Is this what you mean to do? [y/N] 。全部是你要的才打 y 。

    它印出 Sealed card 0x… ，這是卡片的 hash，下一步要用。

  7. 在 Safe web app 提出交易，複製它的 safeTxHash，然後跑
    bin/kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH：它印出 safeTxHash 和一個網頁的路徑，網頁上有 domain hash、message hash 和比對清單，往下走。

    MISMATCH 或 UNVERIFIABLE：不要簽。看它列出的檢查，再看本報告「待確認」裡 AI 的判斷，可能說明原因。

  8. 加強等級：在獨立電腦上跑
    ./check.sh <nonce>

    它算出的 hash 跟硬體錢包比對；它的網頁上的比對清單跟 verify 網頁上的逐列比對。

  9. 硬體錢包上的 domain hash 和 message hash，跟 verify 網頁上的逐字比對，一樣才簽。
    比對domain hash 和 message hash，都是 0x 開頭 64 個字元

程式每次簽名自動做的事

  • 交易只有這 1 個呼叫，MultiSend 也一個個解開
