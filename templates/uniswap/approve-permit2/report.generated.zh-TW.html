授權 Uniswap 的 Permit2 使用一個代幣（無上限）AI 研究

uniswap/approve-permit2

Safe 對你選的代幣呼叫 approve，把無上限的額度給 Permit2。這是 Uniswap app 第一次賣某個代幣前要的授權；Permit2 本身不能動用它，要 Safe 之後在 Permit2 另外授權某個合約（例如 Universal Router）才行。AI 研究

  • 地址來源 7 / 7 7 個地址都至少在 2 個地方確認：官方頁（GitHub 上的檔案算它的 GitHub 組織，跟文件網站是不同的地方）、協議 API、CoinGecko、登記工廠（連同它的檢查問到的其他合約）、Immunefi 漏洞賞金範圍、釘選的 SDK 套件或共用的部署者列出同一個地址。
  • 原始碼驗證 4 / 4 Etherscan 上驗證的原始碼用固定版本的編譯器重新編譯，跟鏈上的程式碼一模一樣，所以解碼交易用的函式定義確實屬於這些合約。permit2 沒有呼叫直接打到，也不用它的函式定義解碼，所以沒有證明，不算在內；它跑的程式碼在「合約沒被換掉」比對。
  • 合約沒被換掉 7 / 7 每次簽名都確認卡片用到的每個合約還是研究時那份程式碼。被升級或換掉就擋下。permit2 沒有 ABI 證明比對它今天的程式碼，報告另外在最新區塊讀它跑的程式碼，跟 code pin 現在那一份比對。
  • 參數保護 沒有測試 模板沒有不限的參數：每個參數都綁定卡片或固定值，沒有參數要換值測試，所以沒有換值測試的記錄。每次簽名，verify 都把每個綁定的參數逐一改掉，確認都變成 MISMATCH。
  • 雙節點比對 所有鏈上資料都同時問兩家節點，答案不一樣就不給結果。
建議無上限授權給 Permit2 會留著；只有 Safe 另外在 Permit2 授權過的合約能用。AI 研究：要小心

過去交易

過去的記錄裡，跟模板一模一樣的有 3 筆：Safe 0 筆、EOA 3 筆（3 個地址，各自送模板的一個呼叫）；形狀一樣、但有地址不在 registry 裡的有 0 筆；形狀不同的有 100 筆，列在其他做法。這些交易全部成功執行：它們是從 usdc Approval時的 Transfer 紀錄找到的，失敗的交易不會留下紀錄。一模一樣的最近 3 筆：0xe9a18108…、0x76b9dade…、0xf4de63ed…。

錨點是所有 USDC 授權，所以不合的多是授權給別的 spender；少數 EOA 給 Permit2 的是固定數量或 0。唯一不合的 Safe 是授權 general-adapter-1 做 Morpho 存款。AI 研究

其他做法

只算用了這個操作的呼叫的交易。跟模板一模一樣，指交易的呼叫和參數位置跟模板相同，從交易本身看得出來的參數規定（例如該填送出者的地方、固定值）都成立，模板綁定 registry 合約的地方也是模板允許的合約。形狀一樣、但用的是 registry 外的市場、代幣、金庫或地址，指呼叫、參數位置和這些參數規定都一樣，但有地址或市場不在 registry 裡；種類照記錄看得出的寫，看不出就只說地址。其他的依原因分組，各附最多 3 筆例子。

下一步

  1. 第一次用這個模板，或模板改過之後，先核准它
    bin/kiss-sign template approve uniswap/approve-permit2

    它印出模板、GitHub 上 main 的 commit 和模板的 keccak256。是你審過的那份才回答 y。

  2. 做卡片
    bin/kiss-sign card new uniswap/approve-permit2

    你這份 clone 的 templates/ 或 registry/ 跟 GitHub 上的 main 不一樣時，它什麼都不問就停下，叫你先跑 git pull 。

  3. 代幣（token）：它列出可選的代幣，每個附完整地址。選你要的那個，名字和完整地址都要對。
  4. 它印出整張卡片，每個名字都附完整地址，最後問 Is this what you mean to do? [y/N] 。全部是你要的才打 y 。

    它印出 Sealed card 0x… ，這是卡片的 hash，下一步要用。

  5. 在 Safe web app 提出交易，複製它的 safeTxHash，然後跑
    bin/kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH：它印出 safeTxHash 和一個網頁的路徑，網頁上有 domain hash、message hash 和比對清單，往下走。

    MISMATCH 或 UNVERIFIABLE：不要簽。看它列出的檢查，再看本報告「待確認」裡 AI 的判斷，可能說明原因。

  6. 加強等級：在獨立電腦上跑
    ./check.sh <nonce>

    它算出的 hash 跟硬體錢包比對；它的網頁上的比對清單跟 verify 網頁上的逐列比對。

  7. 硬體錢包上的 domain hash 和 message hash，跟 verify 網頁上的逐字比對，一樣才簽。
    比對domain hash 和 message hash，都是 0x 開頭 64 個字元

程式每次簽名自動做的事

  • 交易只有這 1 個呼叫，MultiSend 也一個個解開
  • 每個參數符合上面的規則，重新編碼要一模一樣
  • 模擬後 Safe 的餘額一點都不能變
  • 除了上面「交易後」列出可以留著的授權，沒有任何授權在交易後變高
  • 卡片用到的每個登記合約，程式碼還是 code pin 記錄的那份
