Give Uniswap's Permit2 an allowance for one token (unlimited)AI research

uniswap/approve-permit2

The Safe calls approve on the token you pick, giving Permit2 an unlimited allowance. The Uniswap app asks for this allowance before it first sells a token. Permit2 itself cannot use it; the Safe must later give a contract (such as the Universal Router) a separate allowance in Permit2.AI research

  • Address sources 7 / 7 All 7 addresses are confirmed in at least 2 places: the official page (a github.com file counts as its GitHub organization, a place apart from the docs site), the protocol API, CoinGecko, the registered factory (with each other contract its check asks), the Immunefi bug bounty scope, the pinned SDK package or a shared deployer lists the same address.
  • Source verified 4 / 4 The source verified on Etherscan, compiled again with a pinned compiler, gives exactly the code on chain, so the function definitions used to decode the transaction belong to these contracts. permit2: no call goes to it directly and no function definition of it decodes anything, so it has no proof and is not counted; the code it runs is compared under "Code unchanged".
  • Code unchanged 7 / 7 At each signing, the program checks that every contract the card uses still runs the code it was researched with. An upgrade or a replacement is stopped. No ABI proof compares the code permit2 runs today, so the report reads it at the latest block and compares it with the current code pin.
  • Parameter checks no tests The template has no argument that takes any value: each is bound to the card or to a fixed value, so nothing needs a perturbation test and none is recorded. At each signing, verify changes every bound argument one by one and checks that each becomes a MISMATCH.
  • Two providers Every chain read asks two providers; when they disagree, there is no result. Three research reads have one source, and none of them reaches a verdict: past transactions' call traces (drpc), the search for past transactions (a transaction either Alchemy or Etherscan finds counts; only Etherscan searches for an event), and the addresses that ever received a vault's shares (Alchemy; each one's balance is still read through both).
AdviceThe unlimited allowance to Permit2 stays. Only a contract the Safe has separately given an allowance in Permit2 can use it.AI research: be careful

Next steps

  1. Before you approve, open each address's sources in Addresses and check that each domain is the protocol's own and that the page lists the address.
  2. The first time you use this template, or after it changes, approve it
    pnpm kiss-sign template approve uniswap/approve-permit2

    It prints the template, the commit of main on GitHub and the template's keccak256. Answer y only if it is the one you reviewed.

  3. Make the card
    pnpm kiss-sign card new uniswap/approve-permit2

    When templates/ or registry/ in your clone differs from main on GitHub, it stops before asking anything and tells you to run git pull first.

  4. token: it lists each token you can pick, with its full address. Pick the one you want; both its name and its full address must be right.
  5. It prints the whole card, each name with its full address, and asks Is this what you mean to do? [y/N]. Type y only if all of it is what you want.

    It prints Sealed card 0x…, the card's hash, which the next step uses.

  6. Propose the transaction in the Safe web app, copy its safeTxHash, then run
    pnpm kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH: it prints the safeTxHash and the path of a page with the domain hash, the message hash and the checklist. Go on.

    MISMATCH or UNVERIFIABLE: do not sign. Read the checks it lists, then the AI judgment under "To review" in this report, which may explain why.

  7. Hardened tier: on an independent computer, run
    ./check.sh <nonce>

    Compare the hashes it computes with the hardware wallet, and its page's checklist row by row with the verify page.
