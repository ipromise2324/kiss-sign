Give Uniswap's Universal Router a Permit2 allowance for one tokenAI research

uniswap/allow-router

The Safe calls approve on Permit2 so that Universal Router 2.1.2 can pull the token you pick from the Safe through Permit2. The amount is 2^160-1 (Permit2's unlimited), and the app sets the expiry, usually 30 days. The router pulls tokens only from the address that calls it, so only the Safe's own later swaps can use it.AI research

  • Address sources 8 / 8 All 8 addresses are confirmed in at least 2 places: the official page, the protocol API, CoinGecko, the registered factory (for an adapter, with the vault that uses it), the bug bounty scope, the SDK package or a shared deployer lists the same address.
  • Source verified 5 / 5 The source verified on Etherscan, compiled again with a pinned compiler, gives exactly the code on chain, so the function definitions used to decode the transaction belong to these contracts. universal-router-2.1.2: no call goes to it directly and no function definition of it decodes anything, so it has no proof and is not counted; the code it runs is compared under "Code unchanged".
  • Code unchanged 8 / 8 At each signing, the program checks that every contract the card uses still runs the code it was researched with. An upgrade or a replacement is stopped. No ABI proof compares the code universal-router-2.1.2 runs today, so the report reads it at the latest block and compares it with the current code pin.
  • Parameter checks no tests The template has arguments that take any value, but no perturbation test is recorded, so the program has not tested them.
  • Two providers Every chain read asks two providers; when they disagree, there is no result.

Next steps

  1. The first time you use this template, or after it changes, approve it
    bin/kiss-sign template approve uniswap/allow-router

    It prints the template, the commit of main on GitHub and the template's keccak256. Answer y only if it is the one you reviewed.

  2. Make the card
    bin/kiss-sign card new uniswap/allow-router

    When templates/ or registry/ in your clone differs from main on GitHub, it stops before asking anything and tells you to run git pull first.

  3. token: it lists each token you can pick, with its full address. Pick the one you want; both its name and its full address must be right.
  4. It prints the whole card, each name with its full address, and asks Is this what you mean to do? [y/N]. Type y only if all of it is what you want.

    It prints Sealed card 0x…, the card's hash, which the next step uses.

  5. Propose the transaction in the Safe web app, copy its safeTxHash, then run
    bin/kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH: it prints the safeTxHash and the path of a page with the domain hash, the message hash and the checklist. Go on.

    MISMATCH or UNVERIFIABLE: do not sign. Read the checks it lists, then the AI judgment under "To review" in this report, which may explain why.

  6. Hardened tier: on an independent computer, run
    ./check.sh <nonce>

    Compare the hashes it computes with the hardware wallet, and its page's checklist row by row with the verify page.

  7. Compare the domain hash and the message hash on the hardware wallet character by character with the verify page. Sign only if they are the same.
    Comparethe domain hash and the message hash, each 0x followed by 64 characters

What the program does at each signing

  • The transaction has only this call, counting each call inside a MultiSend
  • Every argument follows the rules above, and encoding them again gives exactly the same bytes
  • After simulation, no balance of the Safe may change at all
  • No allowance is higher after the transaction, except those "After the transaction" above lists as allowed to remain
  • Every registry contract the card uses still runs the code its code pin records
