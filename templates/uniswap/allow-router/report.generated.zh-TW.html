uniswap/allow-router

Safe 呼叫 Permit2 的 approve，讓 Universal Router 2.1.2 能透過 Permit2 從 Safe 拉你選的代幣，數量 2^160-1（Permit2 的無上限），到期時間由 app 設，通常 30 天。router 只從呼叫它的地址拉代幣，所以只有 Safe 自己之後的兌換能用。AI 研究

  • 地址來源 8 / 8 8 個地址都至少在 2 個地方確認：官方頁（GitHub 上的檔案算它的 GitHub 組織，跟文件網站是不同的地方）、協議 API、CoinGecko、登記工廠（連同它的檢查問到的其他合約）、Immunefi 漏洞賞金範圍、釘選的 SDK 套件或共用的部署者列出同一個地址。
  • 原始碼驗證 5 / 5 Etherscan 上驗證的原始碼用固定版本的編譯器重新編譯，跟鏈上的程式碼一模一樣，所以解碼交易用的函式定義確實屬於這些合約。universal-router-2.1.2 沒有呼叫直接打到，也不用它的函式定義解碼，所以沒有證明，不算在內；它跑的程式碼在「合約沒被換掉」比對。
  • 合約沒被換掉 8 / 8 每次簽名都確認卡片用到的每個合約還是研究時那份程式碼。被升級或換掉就擋下。universal-router-2.1.2 沒有 ABI 證明比對它今天的程式碼，報告另外在最新區塊讀它跑的程式碼，跟 code pin 現在那一份比對。
  • 參數保護 沒有測試 模板有不限的參數，但沒有換值測試的記錄，程式沒有測過它們。
  • 雙節點比對 所有鏈上資料都同時問兩家節點，答案不一樣就不給結果。

過去交易

這個操作沒有研究過去交易。

下一步

  1. 第一次用這個模板，或模板改過之後，先核准它
    bin/kiss-sign template approve uniswap/allow-router

    它印出模板、GitHub 上 main 的 commit 和模板的 keccak256。是你審過的那份才回答 y。

  2. 做卡片
    bin/kiss-sign card new uniswap/allow-router

    你這份 clone 的 templates/ 或 registry/ 跟 GitHub 上的 main 不一樣時，它什麼都不問就停下，叫你先跑 git pull 。

  3. 代幣（token）：它列出可選的代幣，每個附完整地址。選你要的那個，名字和完整地址都要對。
  4. 它印出整張卡片，每個名字都附完整地址，最後問 Is this what you mean to do? [y/N] 。全部是你要的才打 y 。

    它印出 Sealed card 0x… ，這是卡片的 hash，下一步要用。

  5. 在 Safe web app 提出交易，複製它的 safeTxHash，然後跑
    bin/kiss-sign verify --card <card hash> --safe-tx-hash <safeTxHash>

    MATCH：它印出 safeTxHash 和一個網頁的路徑，網頁上有 domain hash、message hash 和比對清單，往下走。

    MISMATCH 或 UNVERIFIABLE：不要簽。看它列出的檢查，再看本報告「待確認」裡 AI 的判斷，可能說明原因。

  6. 加強等級：在獨立電腦上跑
    ./check.sh <nonce>

    它算出的 hash 跟硬體錢包比對；它的網頁上的比對清單跟 verify 網頁上的逐列比對。

  7. 硬體錢包上的 domain hash 和 message hash，跟 verify 網頁上的逐字比對，一樣才簽。
    比對domain hash 和 message hash，都是 0x 開頭 64 個字元

程式每次簽名自動做的事

  • 交易只有這 1 個呼叫，MultiSend 也一個個解開
  • 每個參數符合上面的規則，重新編碼要一模一樣
  • 模擬後 Safe 的餘額一點都不能變
  • 除了上面「交易後」列出可以留著的授權，沒有任何授權在交易後變高
  • 卡片用到的每個登記合約，程式碼還是 code pin 記錄的那份
